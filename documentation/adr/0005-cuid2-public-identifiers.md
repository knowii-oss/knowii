# 0005. cuid2 public identifiers, slugs for page URLs

- Status: Accepted
- Date: 2026-11-09
- Pull request: #1168

## Context

Integer keys in URLs leak the size and growth of the data and invite enumeration. ULID and UUIDv7 expose the creation time. Members also want readable page URLs.

## Decision

1. Every table has an internal `id` (big integer, used for keys and joins) and a public `cuid` (cuid2, generated by `App\Traits\GeneratesCuid`).
2. APIs, channels and events use the `cuid`. Models hide `id` and foreign keys when serialized.
3. Page URLs use slugs (`cviebrock/eloquent-sluggable`), unique within their parent.

## Consequences

1. API route model binding uses `cuid` (`getRouteKeyName()`).
2. Renaming something changes its slug, so old page URLs break unless a redirect is kept (to handle when it matters, for example in the Circle migration).

## Alternatives considered

1. UUIDv4: longer, no benefit over cuid2.
2. ULID or UUIDv7: expose the creation time.
